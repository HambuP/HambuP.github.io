Software Rasterizer

A 3D renderer that runs entirely on the CPU, written from scratch in C++ to understand how 3D graphics actually work. SDL3 only opens the window and shows the finished framebuffer.

DOCUMENTATION ↗ BUGS HALL OF FAME ↗ HANDWRITTEN NOTES ↗ SOURCE ON GITHUB ↗
WHY I BUILT THIS

“Honestly, it was pure curiosity.”

It started in Lua with one goal: understanding how 3D graphics work. When Lua got complicated, I started over in C++ with the right tools.

Building the base of 3D rendering taught me how linear algebra is actually used, how to structure a project, how to fix bugs, how to optimize, and how to turn an idea into something huge. I built every part from scratch, so I can explain any part of it to anyone. That is what I love most: teaching.

IN MOTION
PIPELINE
  • Math library from scratch: Vec2, Vec3, Vec4, Mat4
  • Full Model · View · Projection, every matrix derived on paper first
  • Near-plane triangle clipping, frustum rejection, back-face culling
  • Barycentric rasterization with perspective-correct interpolation
  • Per-pixel z-buffer
LIGHTING AND SHADING
  • Per-pixel Phong: ambient, diffuse, specular
  • Toon shading with banded light and outlines, switchable per object
  • Directional light and spotlight with cone and attenuation
  • Shadow maps: orthographic for the directional light, perspective for the spotlight
  • Bias against shadow acne; shadow maps re-render only when a light changes
ASSETS
  • OBJ parser with MTL materials
  • Quads and n-gons split into triangles
  • BMP decoder written from scratch, 24-bit and 32-bit
PERFORMANCE AND INTERACTION
  • Multithreaded: the screen and the shadow maps split into bands of rows, one per CPU core
  • First-person camera: WASD and mouse look
RELEASE BUILD · 800×600 · APPLE M5
SORT

Going from 22 triangles to 160K only drops from ~200 to ~150 FPS. Most of the frame goes to shading every pixel on screen, not to the number of triangles.

You need CMake 3.24+ and a C++17 compiler. CMake downloads and builds SDL3 for you the first time. Build in Release: Debug runs several times slower.

git clone https://github.com/HambuP/software-rasterizer.git
cd software-rasterizer
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
# run from the repo root so it finds obj/
./build/Rasterizer              # Linux / macOS
build\Rasterizer.exe            # Windows (MinGW)
build\Release\Rasterizer.exe    # Windows (Visual Studio)

Tested with MinGW GCC 15.2 on Windows and GCC 13 on Linux. On Linux, SDL3 needs your X11/Wayland development packages. The code comments are in Spanish, my first language; the documentation is in English.
